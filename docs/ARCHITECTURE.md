## 1. High-Level Architecture

```
┌─────────────────────────────────────┐         ┌─────────────────────────────────────┐
│   BROWSER (React 18 + TS + Vite)    │  HTTP   │   FLASK REST API (gunicorn)         │
├─────────────────────────────────────┤ ──────> ├─────────────────────────────────────┤
│ • Executive recommendation hero     │  JSON   │ • API-key auth · CORS allowlist     │
│   (feasibility-first)               │ <────── │ • Rate limiting · input validation  │
│ • Vessel comparison table           │         │ • /api/health                       │
│ • Route map + voyage risk           │         │ • /api/procurement/evaluate         │
│ • What-If stress-test simulator     │         │   (POST, validated)                 │
│   (client engine, shared config)    │         │ • /api/procurement/ports|routes     │
│ • Open-Meteo port weather           │         │ • /api/market/latest                │
└─────────────────────────────────────┘         │ • /api/forecast/freight             │
        │                                       │ • /api/models/evaluation            │
        ▼                                       └────────────────┬────────────────────┘
┌─────────────────────────────────────┐                          ▼
│  shared/engine_config.json          │         ┌─────────────────────────────────────┐
│  (single source of truth: ports,    │ <────── │  PYTHON ENGINE (procurement/)       │
│  routes, vessels, cargo, costs)     │  loads  │  deterministic cost & feasibility   │
└─────────────────────────────────────┘         └─────────────────────────────────────┘
        ▲
        │ generated by
┌─────────────────────────────────────┐
│  shared/derive_distances.py         │
│  (great-circle + detour factors;    │
│   Suez waypoint routing)            │
└─────────────────────────────────────┘
```

**Design rules**

1. **One config, two engines.** All engine parameters live in `shared/engine_config.json`. The Python engine (authoritative, served via the API) and the TypeScript engine (client-side what-if simulator) both load it — data drift between them is structurally impossible.
2. **Feasibility before economics.** Draft infeasibility is a hard flag (`is_feasible=false`), never a soft penalty. The recommendation hero only ever showcases a physically feasible vessel; if none exists it renders an explicit "no feasible charter" advisory.
3. **Fail loudly, never fabricate.** If the market feed or dataset is unavailable, the API returns `503` with provenance `UNAVAILABLE` and the UI shows an explicit error — invented "fallback data" is restricted to `DEMO_MODE=1` and always labeled synthetic.
4. **No unauthenticated wildcard API.** API keys, a CORS allowlist, rate limiting and strict input validation are built into the app factory.

## 2. Component Responsibilities

### A. Shared engine configuration (`shared/`)
- `engine_config.json` — ports (coordinates, draft limits, waiting days), 24 lane distances, vessel specs (capacity/speed/fuel/hire/draft), cargo profiles, cost constants (port charge, Suez fee, demurrage buffers, index→$/MT conversion), canal-lane map.
- `derive_distances.py` — regenerates the config's distances from port coordinates using great-circle (haversine) math × documented detour factors; US Gulf lanes routed via Suez waypoints (4 legs + fixed 120 NM canal transit). This is the project-owned, vendor-independent distance method.

### B. Procurement engine (`procurement/procurement_engine.py`)
- Pure deterministic functions: `evaluate_all_vessels(...)` → per-vessel feasibility, cost breakdown (freight/bunker/port+canal/demurrage per MT), utilization, stowage-cube check, decision score; `get_route_risk_profile(...)` → derived lane exposure.
- Validation: non-positive quantities, unknown routes, unknown cargo types, non-finite numbers all raise `ValueError` (surfaced as HTTP 400).
- Risk levels are plain enums (`Low/Medium/High`); emoji live only in the render layer.

### C. Backend API (`backend/`)
- `app/__init__.py` — app factory: API-key gate (`API_KEYS`), CORS allowlist (`CORS_ALLOWED_ORIGINS`), sliding-window rate limiter (`RATE_LIMIT_PER_MINUTE`), body-size cap, `nosniff`, sanitized 4xx/5xx handlers.
- `app/security.py` — limiter + env parsing (stdlib only).
- `app/routes/api.py` — endpoints; `evaluate` validates bounds (cargo 100–400,000 MT, bunker $50–2,000/MT, multiplier 0.1–5.0), rejects `NaN`/`Infinity`, and enforces known cargo types.
- `app/services/market_service.py` — FX (Yahoo → Open-ER → Frankfurter) and crude spot (WTI → Brent) with thread-pool timeouts; ESTIMATED bunker = crude × 7.33 (clearly disclosed as crude-equivalent, not a VLSFO assessment); thread-safe TTL cache.
- `app/services/forecast_service.py` — dampened-momentum 30-day trend corridor from the BDRY ETF dataset with **empirically calibrated error-quantile bands and a walk-forward backtest** (accuracy + out-of-sample band coverage computed on every cache refresh); error-aware timing signal (fires only beyond the measured error bar); locked + TTL cache; `DEMO_MODE=1` synthetic fallback, always labeled; `None` (→ 503) on data failure.
- `run.py` (dev, `HOST=127.0.0.1`, debugger off by default) and `gunicorn.conf.py` (production).

### D. Frontend (`frontend/`)
- `services/api.ts` — timeout-guarded fetch layer; base URL from `VITE_API_URL` (default same-origin `/api`); optional `VITE_API_KEY`; response shape validation.
- `App.tsx` — mount-once bootstrap; debounced (300 ms) parameter-driven re-evaluation; explicit error banners (evaluation, market, forecast); 10 s reconnect polling while offline.
- `lib/procurementEngine.ts` — TS port of the engine importing the shared JSON config (used by the what-if simulator).
- Components render risk/feasibility as UI (emoji mapping in the render layer only).

### E. ML (`ml/`)
- Training/evaluation scripts and the honesty audit (`evaluate_ml_models.py`, `model_honesty_check.py`, `baseline_model.py`). Outputs: `ml/reports/model_performance_evaluation.json` + confusion matrices. ML is excluded from decision logic (see Model Honesty report).

## 3. API Surface

| Endpoint | Method | Notes |
|:---|:---|:---|
| `/api/health` | GET | Open (LB probes); version + timestamp |
| `/api/procurement/evaluate` | POST | Validated; returns ranked evaluations + risk profile + echoed parameters |
| `/api/procurement/ports` | GET | Port coordinates, drafts, provenance citations |
| `/api/procurement/routes` | GET | Derived lane distances |
| `/api/procurement/risk-profile` | GET | Derived lane exposure |
| `/api/market/latest` | GET | FX (LIVE) + bunker estimate (ESTIMATED); `503` when feeds unavailable |
| `/api/forecast/freight` | GET | 30-day trend projection; `503` when dataset unavailable (no fabrication) |
| `/api/models/evaluation` | GET | ML audit report; `404` when absent |

When `API_KEYS` is set, all of the above except `/api/health` require `X-API-Key`. Rate-limit breaches return `429` with `Retry-After`.

## 4. Deployment

### Backend
```bash
pip install -r requirements.txt
gunicorn -c backend/gunicorn.conf.py backend.run:app   # BIND=0.0.0.0:5000 by default
```
Environment: `API_KEYS`, `CORS_ALLOWED_ORIGINS`, `RATE_LIMIT_PER_MINUTE`, `BIND`, `WEB_CONCURRENCY`, `DEMO_MODE` (never in production). Put TLS termination (reverse proxy / platform TLS) in front; never expose the Flask dev server.

### Frontend
```bash
cd frontend && npm run build   # dist/
```
Host `dist/` behind the same domain as the API (or set `VITE_API_URL` at build time). Same-origin deployment avoids CORS entirely.

### CI
`.github/workflows/ci.yml` — Python 3.12: engine + API suites; Node 20: lockfile-exact install, typecheck, production build.

## 5. Known Debt & Roadmap

- **Dev-dependency advisories**: `npm audit` flags the Tailwind 3 glob chain (`braces`/`micromatch`) and Vite 5's dev server (`esbuild`). None ship in the production bundle; remediation requires the Tailwind 4 + Vite 8 major-version migration (planned).
- **Market feeds** are dev-time (Yahoo ToS) — must be replaced per [DATA_PROVENANCE.md](docs/DATA_PROVENANCE.md) §3 before charging customers.
- **Single-process rate limiter** (in-memory) — acceptable at pilot scale; move to Redis-backed limiting for multi-worker/multi-node production.
- **No persistence yet** — users, tenancies, saved scenarios and audit logs arrive with v1.1 (PostgreSQL + auth provider) per the commercialization roadmap.
